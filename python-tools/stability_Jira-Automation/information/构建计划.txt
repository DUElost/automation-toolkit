项目：JIRA Monkey测试问题自动化管理系统 - 最终构建方案
一、 项目愿景与目标
本项目旨在构建一个高效、智能、可扩展的自动化系统，用于端到端地管理Monkey测试产生的JIRA稳定性问题。系统将取代当前繁琐的手动处理流程，通过一个以PostgreSQL为决策引擎、Python为业务粘合剂的高度自动化工作流，实现问题的智能去重、自动流转和数据沉淀，最终大幅提升测试和研发团队的缺陷处理效率。

二、 总体架构设计
系统采用多层架构，核心思想是将数据准备（Python）、决策计算（PostgreSQL） 和 任务执行（Python） 三个阶段清晰分离，以获得最高的处理性能和可维护性。

数据流向:

数据输入: 系统从本地文件系统读取由start_log_scan工具生成的Excel结果清单，同时通过API从飞书多维表格拉取所有业务规则（如：模块映射、人员指派、判重阈值等）。

数据预处理: Python应用负责解析Excel和飞书数据，进行清洗、格式化、字段映射、定级，并组装成标准化概要和测试环境等中间数据。

高性能决策: 预处理后的数据被加载到PostgreSQL。利用其强大的pg_trgm插件，数据库本身将作为一个高性能计算引擎，通过单次SQL查询，完成所有新问题与历史问题的模糊匹配和相似度计算，并生成最终执行计划（CREATE, UPDATE, REOPEN, CLOSE_PASS）。

指令执行: Python应用读取数据库中的执行计划，调用JIRA API，对JIRA平台进行精确、批量的写操作。

数据同步: 定时任务将JIRA的最新状态同步回PostgreSQL，形成数据闭环，为下一次决策提供最新的历史数据。

三、 核心模块构建方案
模块一：数据处理与规范化引擎

职责: 系统的“数据准备中心”，负责将所有异构的输入源转化为统一的、可供决策的结构化数据。

技术栈: Python, pandas, lark-oapi

关键任务:

配置读取: 通过lark-oapi库连接飞书，获取并缓存以下配置信息：

黑白名单。

Package -> 模块 对应表。

模块 -> 经办人 对应表。

问题等级（bugSeverity）定级规则。

判重相似度阈值（如：env_threshold: 0.99, cause_threshold: 0.90）。

原始数据解析: 使用pandas读取Excel，提取Path, Version, ExpClass, ExpType, CurProcess, Package, Detail, CausedBy, Count, DeviceCount等所有必需字段。

工单数据生成:

应用黑白名单进行数据过滤。

执行所有字段的映射、定级和格式化。

组装测试环境字段: 将Package, ExpClass, CurProcess, CausedBy拼接为标准字符串。

生成标准化概要: 移除概要中的版本号、报错次数等易变信息，生成用于搜索的干净字符串。

输出: 一个包含JIRA字段和决策辅助字段（测试环境, 报错原因, 标准化概要）的结构化数据集。

模块二：数据库同步与高性能决策模块

职责: 系统的“大脑”，负责存储历史状态，并以极高性能完成复杂、模糊的判重决策。

技术栈: PostgreSQL (核心), psycopg2

关键任务:

JIRA数据同步: 定时将JIRA问题拉取至本地jira_issues_main表，此表包含用于决策的所有字段，特别是normalized_summary和test_environment。

高性能决策引擎:

将模块一生成的数据集批量载入数据库临时表pending_issues。

Python从飞书获取阈值，然后构建并执行一个单次SQL查询，利用pg_trgm的similarity()函数和GIN索引，直接在数据库中完成所有pending_issues与jira_issues_main的批量模糊匹配。

Python获取SQL返回的匹配结果（重复项），据此在pending_issues表中标记最终action (CREATE, UPDATE, REOPEN)。

执行反向逻辑，标记CLOSE_PASS任务。

模块三：JIRA执行器

职责: 系统的“手臂”，忠实地执行数据库中的最终决策。

技术栈: Python, jira-python

关键任务:

读取pending_issues表中待执行的任务。

根据action字段，调用jira.create_issue(), jira.add_comment(), jira.transition_issue()等相应函数，完成对JIRA的批量操作。

记录详细的操作日志，并将JIRA返回的新Key等信息回写到数据库，用于追踪。

四、 数据库设计与配置
数据库系统: PostgreSQL 12+

核心插件 (必须启用): pg_trgm。

执行 CREATE EXTENSION IF NOT EXISTS pg_trgm;

核心表结构 (jira_issues_main):
| 列名 | 数据类型 | 索引 | 备注 |
| :--- | :--- | :--- | :--- |
| id | SERIAL | PRIMARY KEY | 自增主键 |
| jira_key | VARCHAR(255) | UNIQUE | JIRA问题Key，如VFFBA-1234 |
| status | VARCHAR(100) | INDEX | 问题状态 |
| summary | TEXT | | 原始概要 |
| normalized_summary| TEXT | INDEX | 标准化后的概要，用于精确匹配 |
| test_environment| TEXT | GIN | 测试环境完整信息 |
| raw_caused_by| TEXT | GIN | 报错原因完整信息 |
| assignee | VARCHAR(255) | | 经办人 |
| ... | ... | | 其他所需字段 |

关键索引: 必须为test_environment和raw_caused_by字段创建GIN索引以保证查询性能。

CREATE INDEX idx_gin_test_environment ON jira_issues_main USING gin (test_environment gin_trgm_ops);

CREATE INDEX idx_gin_raw_caused_by ON jira_issues_main USING gin (raw_caused_by gin_trgm_ops);

五、 技术栈选型
编程语言: Python

核心库: psycopg2-binary, pandas, openpyxl, lark-oapi, jira-python

数据库: PostgreSQL (已启用pg_trgm插件)

缓存 (可选): Redis (用于缓存飞书配置，降低API调用)

监控 (可选): Zabbix / Prometheus (监控自动化脚本的运行状态和健康度)

部署: Docker (推荐，用于打包Python应用和数据库，实现环境一致性)
